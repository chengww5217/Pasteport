## [0.0.2] - 2026-08-27

### 追加

- インターフェースを簡体字中国語、繁体字中国語、日本語、韓国語、フランス語、ドイツ語、スペイン語、
  ロシア語、ブラジル ポルトガル語にローカライズし、VS Code 自体の表示言語に追従するようになりました。
  コマンド名と設定の説明は `package.nls.*.json` から、ダイアログと通知は
  `l10n/bundle.l10n.*.json` から来ます。ログ出力は意図的に英語のままです。バグ報告が運ぶものだから
  です。
- 翻訳されたドキュメント: `docs/README.zh-CN.md`、`docs/README.zh-TW.md`、`docs/README.ja.md`、
  および `docs/CHANGELOG.<locale>.md` にある各言語の変更履歴。すべての README と変更履歴の先頭から
  相互にリンクされています。これらは vsix には含まれず、マーケットプレイスには英語版が表示されます。
- `Pasteport: Show Resolved Remote Directory`（解決済みのリモートディレクトリを表示）を追加しました。
  貼り付けで実際に使われるディレクトリを確認できます。`pasteport.remoteDir` 設定の説明には、入力欄の
  すぐ横にこのコマンドへのリンクが付いています。

### 変更

- Linux では、ステージングしたクリップボード画像はユーザーごとのディレクトリ — OS の一時ディレクトリの
  下にある `pasteport-staging-<uid>` — に置かれ、`0700` で作成されます。従来の固定名は誰でも書ける共有の
  `/tmp` にあり、同じマシンの別のユーザーが通過するスクリーンショットをすべて読めたり、ミリ秒の
  タイムスタンプだけという予測可能な名前でディレクトリを先に作ってシンボリックリンクを仕込めたり
  しました。macOS と Windows はもともとユーザーごとにプライベートな一時ディレクトリを渡すため、
  そちらは変わりません。`Pasteport: Diagnose` が使用中のパスを表示します。
- `pasteport.remoteDir` の既定値が空になり、「検出する」という意味になりました。リモート ホスト自身の
  `TMPDIR` を `workspace.fs` 経由でリモート サーバー プロセスの環境（`/proc/self/environ`）から読み
  取り、失敗した場合は `/tmp` と `/var/tmp` のうち先に存在するものへ、さらに警告付きで `/tmp` へ
  フォールバックします。ファイルは選ばれたディレクトリの `pasteport` サブディレクトリに置かれます。
  `TMPDIR` を別の場所に向けているホストも、いまはその設定どおりに扱われます。値を明示的に設定すれば
  従来どおり検出はスキップされます。検出にかかるのは数回の読み取りだけで、リモート ホストごとに
  セッションで 1 回だけです。
- `pasteport.remoteDir` は他の設定と同様のユーザー設定になり、開いているワークスペースから上書きされる
  可能性があるため、リポジトリが貼り付け先を決めることもできます。設定の説明と README では、信頼できる
  ワークスペースでのみ貼り付けるよう注意を促しています。
- `Pasteport: Diagnose` が、設定されたリモート ディレクトリと解決されたリモート ディレクトリを
  並べて報告します。

### 修正

- 転送中に貼り付けキーを押しても何も起きない、ということがなくなりました。拡張機能自身の処理は
  破棄されますが、キー入力は従来どおりターミナルへ渡されます。
- クリップボード リーダーが例外を投げた場合にも、貼り付けキーが通るようになりました。本来はどの
  リーダーもエラー ペイロードを返して終わるもので、例外は想定外です。以前はそのような例外でキー入力が
  飲み込まれてしまっていました。
- リモート ディレクトリの検出にタイムアウトが設けられ、ホストが実際に応答したときだけ結果を記憶
  します。リモート ファイル システムがまだ応答していない時点で走った検出が、セッションの残り全部で
  `/tmp` を固定してしまうことはなくなり、半死のコネクションが貼り付けコマンドを永遠に待たせることも
  なくなりました。
- リモートのファイル名からバック クォートと `$` が取り除かれるため、``x`id`.png`` という名前の
  ファイルがコマンド置換をプロンプトへ持ち込むことはなくなりました。他のシェル メタ文字はそのまま
  です。`(` と `)` はスクリーンショット名では普通なので、そのまま貼り付けられた名前は、行をシェルが
  解析する場合には引き続き `quoting: shell` が必要になることがあります。
- Windows のリーダーは、ステージング前にクリップボードの `PNG` フレーバーのバイト列が本当に PNG か
  （先頭のマジックバイトで）を検証するようになりました。クリップボードには `PNG` と名乗るだけで
  中身が PNG でないデータが紛れ込むことがあり、検証に失敗したらビットマップから本当の PNG を
  生成し直します（Linux のリーダーは以前から同じです）。読み取ったクリップボード ストリームも破棄します。
- Linux のインストール ヘルパーは、パッケージ マネージャーと `pkexec` を名前ではなく見つけた絶対
  パスで起動します。このコマンドは root として実行されるためです。
- 数千個のファイルを保持したクリップボードが `ENOBUFS` でリーダーを落とすことはなくなりました。
  出力上限が 1 MB から 8 MB になりました。そのパイプを通るのはパスだけで、画像のバイト列は決して
  通りません。
- `release.yml` はタグのバージョンをコマンド ラインに埋め込むのではなく、環境変数でシェルに渡します。

## [0.0.1] - 2026-08-24

[VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=chengww.pasteport) と
[Open VSX](https://open-vsx.org/extension/chengww/pasteport) で公開しました。

### 追加

- macOS のクリップボードにある画像とファイルを VS Code のリモート ウィンドウのターミナルへ貼り付け、
  リモート パスをプロンプトに挿入します。
- 転送はウィンドウから借りた URI を使う `workspace.fs` 経由なので、どのリモート バックエンドも同じ
  コード パスを通ります。Remote - SSH でエンド ツー エンドに検証済みです。
- フィンガープリントによる重複排除: 8 MB までは内容の SHA-256、それを超えると `size:mtime:name`。
  リモートに正しいサイズのコピーが既にあれば、再送せずにそれを再利用します。
- 最初の 1 ミリ秒からステータス バーに進捗を表示。`pasteport.confirmAboveSeconds` を超えると
  見込まれる転送には確認ダイアログとキャンセル可能な通知を出します。見積もりは自分のリンクで実測した
  スループットに基づきます。
- アップロードしたファイルとローカルにステージングした画像の TTL クリーンアップ。起動時にバック
  グラウンドで実行され、`Pasteport: Clean Up Remote Files` からも実行できます。
- `Pasteport: Diagnose`。貼り付けの成功が依存するすべての条件を報告します。
- 設定: `remoteDir`、`quoting`、`trailingSpace`、`confirmAboveSeconds`、`ttlHours`、
  `bracketedPaste`。
- Windows クライアント対応: クリップボードに PNG フレーバーがあればそれを、なければビットマップを
  取る PowerShell リーダー。<kbd>Ctrl</kbd>+<kbd>V</kbd> に割り当てられます。
- Linux クライアント対応: Wayland では `wl-paste`、X11 では `xclip`。`text/uri-list` と
  `x-special/gnome-copied-files` を処理し、<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>V</kbd> に
  割り当てられます。
- Linux のクリップボード ツールが無い場合のインストール提案: コマンドは実行前に提示され、権限昇格は
  `pkexec` を通すのでデスクトップ自身が認証を求めます。未対応のディストリビューションやソース
  ベースのものには、推測せずに何を実行すべきかを伝えます。
- `pasteport.paste` を `terminal.integrated.commandsToSkipShell` に登録します。これがないと
  Windows では貼り付けキーがシェルへ届き、拡張機能には決して届きません。
- 拡張機能のアイコン。パッケージ時に `scripts/build.mjs` が `assets/icon.svg` からラスタライズ
  します。画像はリポジトリにコミットしません。
- esbuild でのパッケージング: 拡張機能は最小化された 1 つの `dist/build/extension.js` として配布
  され、vsix にはテストもソース マップも含まれません。

### 既知の制限

- Windows と Linux のリーダーは、まだ実際のデスクトップ セッションで人間に使われていません。どちらも
  ユニット テストで覆われており、Windows のものは CI で実際の PowerShell に対して走ります。
- PowerShell の起動コストは実機で未計測です。プレーン テキストの貼り付けを含め、毎回の貼り付けに
  かかります。プローブが 150ms を超えると拡張機能が警告をログに出します。
- バックエンドとして検証済みなのは Remote - SSH だけです。Dev Containers、WSL、Tunnels は同じ
  コード パスを使いますが、まだ実際には使われていません。
- TUI エージェントでの引用符の扱いが未検証のあいだ、`quoting: auto` はパスをそのまま挿入します。
- 進行中の転送はファイルの途中で中断できません。`workspace.fs.writeFile` にキャンセル ポイントが
  ないため、キャンセルはファイルの間で転送を止めます。
